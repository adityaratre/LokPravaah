# LokPravaah Cloudflare UPI Gateway

This Worker provides the donation checkout endpoints used by LokPravaah and receives signed notifications from the receiving-account Android observer. Payment sessions and device pairing records are stored in Supabase. It is not a regulated payment aggregator or a bank integration; a UPI QR by itself is never proof of payment.

## Routes

- `GET /health`
- `GET /youpi.js`
- `GET /qr.js` and `GET /qr-lib.js`
- `POST /api/v1/payments`
- payment status, cancellation, and `/checkout/:id` endpoints
- Android observer pairing, heartbeat, and signed notification endpoints
- `POST /api/v1/admin/sms-gateway/pair-qr` — requires a valid Supabase access token belonging to a `super_admin` user
- `GET /admin` — intentionally returns 404; there is no standalone gateway admin page

The receiving-device pairing UI lives inside the website at **Admin Console → Platform controls → Donations & UPI → UPI observer pairing**. The browser sends the current Supabase session access token. The Worker independently verifies it against Supabase Auth and reads the user's role using the server-side service-role key. No static `ADMIN_API_TOKEN` is required or placed in browser storage.

## Deploy

1. Keep the website on Cloudflare Pages and deploy the Worker as `lokpravaah-upi-gateway` using `wrangler.jsonc`.
2. Keep the Worker attached only to the listed path routes on `lokpravaah.online`; do not make it a Custom Domain for the entire root hostname.
3. In Worker Settings → Variables and Secrets, configure `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (secret), `LOKPRAVAAH_DONATION_WEBHOOK_URL`, `LOKPRAVAAH_DONATION_WEBHOOK_SECRET` (secret), `UPI_VPA`, `UPI_PAYEE_NAME`, `LOKPRAVAAH_FRONTEND_ORIGIN=https://lokpravaah.online`, `MERCHANT_ID`, `PUBLIC_BASE_URL=https://lokpravaah.online`, and `PAYMENT_SESSION_MINUTES=15`.
4. In the same Supabase project, apply `supabase/lokpravaah_donations.sql` if not already applied, then `supabase/lokpravaah_cloudflare_gateway.sql`.
5. In Cloudflare Pages, set `VITE_DONATION_GATEWAY_PORTAL_URL=https://lokpravaah.online`, `VITE_DONATION_GATEWAY_API_URL=https://lokpravaah.online`, and `VITE_DONATION_MERCHANT_KEY=00000000-0000-0000-0000-000000000001`, then rebuild the website.
6. Set Supabase Edge Function secret `DONATION_WEBHOOK_SECRET` equal to `LOKPRAVAAH_DONATION_WEBHOOK_SECRET` and deploy the `donation-webhook` function with HMAC verification enabled in its handler.

Never commit `.dev.vars`, the Supabase service-role key, webhook secrets, or other private values. Never add service-role keys or webhook secrets to `VITE_` variables.

## Verify

From `cloudflare-upi-worker`, run `npm test` and `npm run check`. After deployment, `https://lokpravaah.online/health` checks configuration and database reachability; it does not prove that real UPI payments work. Sign in to the website as a super administrator and generate the QR from the existing Admin Console. Pair only the receiving-account Android phone and test a small real payment before relying on auto-verification. The payment is confirmed only when a signed bank notification is matched and the donation webhook verifies the matching order and amount.

The Worker and UI changes still require deployment to the user's Cloudflare/GitHub project, applying the SQL to the live Supabase project, and an end-to-end test. Local unit tests alone do not verify those external steps.


## Android observer download

The current YOUPI Android observer build is generated by the `build-android-observer.yml` workflow and published as `public/youpi-sms-gateway.apk`. The Cloudflare Worker serves it at:

- `https://lokpravaah.online/youpi-sms-gateway.apk`

Install the updated build when the older observer shows only a generic pairing error. Pair with a newly generated one-time QR/token. A token that was already used or has expired is intentionally rejected. The APK is a debug-signed test build; if Android refuses to update because the signing certificate differs, back up the current setup, uninstall the older app, install the new build, then grant notification/battery permissions and pair again.
